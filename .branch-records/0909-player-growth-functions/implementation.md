# 玩家函数成长 V2

## Effective behavior (2026-09-09)
- Players in sword1/demo/sword2 use six fixed profiles from packages/types/src/player-growth-parameters.ts. Unknown game slugs retain authored legacy behavior.
- Attribute A(L)=floor(a+b*((1+(L-1)/10)^p-1)+1e-8), levels 1..1000. All six core attributes retain original L1 and reach ceil(original*1.05) at L80 (sword1/demo) or L60 (sword2). Additional base attack2/3/defend2/3 are zero in audited source; equipment, magic and permanent deltas remain additive.
- C(L)=ceil(k*L^q*exp(r*(1-exp(-((L-1)/40)^2)))), for L<1000; enter-level experience is sum of preceding costs. Exact thresholds advance; binary search supports multiple levels. At L1000 retain accumulated baseline, next threshold 0, stop character experience but continue magic kill experience.
- No piecewise formulas, no runtime fitting. Cumulative thresholds alone are cached; attributes use the function. Source baseline retained in original-levels.json (public numeric configuration only). Original cumulative experience includes sword2 regressions (easy 7->8,46->47; hard7->8); new thresholds are monotonic. Fit and design were reviewed in the current conversation; this is not a claim of validated combat/real-time leveling balance.

## Call relationships and compatibility
- packages/types/src/player-growth.ts is the single math API consumed by PlayerGrowth and dashboard PlayerGrowthPreview. Original public REST/tRPC level contracts and stored rows are unchanged for older clients and partners.
- Player.growth delegates Player.addExp/levelUpTo/setLevelTo/initialization and recalculation. It does not replace LevelManager shared with partners. Character.calculateBaseStats composes a supplied baseline with learned magic and equipment; legacy Character.recalculateBaseStats still uses authored rows.
- SaveDataCollector adds growth metadata (version/profile/permanent residuals) independently of flat fields. loadFromSaveData snapshots original totals BEFORE async equipment callbacks; final recalculation runs after containers are loaded. New metadata uses recorded bonuses; legacy saves derive residuals from saved totals minus old baseline/magic/equipment. This intentionally preserves historical residuals, including those whose provenance cannot be distinguished from old bugs. Zero/death and HP/thew/mana ratios survive migration.
- Experience migration preserves saved level and within-level completion, not the old cumulative total. Old capped/reset experience resumes at its saved level's start. Difficulty switches use old/new function intervals. Subsequent loads and equal-cost difficulty switches preserve integer experience directly to avoid repeated rounding drift. Living players retain at least one HP after ratio conversion; dead players stay at zero.
- SavePlayer/LoadPlayer script snapshots carry growth metadata and secondary stats. Debug/script set-level funnels through Player.setLevelTo and clamps to 1..1000.
- A formerly controlled actor now keeps separate player and partner progress in CharacterProfile.player/partner; inventories and magic stay shared. First conversion to partner clamps into the legacy table and converts progress; subsequent partner flushes cannot overwrite the formula player's level/experience/permanent bonuses. This is necessary because their caps and curves differ. Uncontrolled legacy NPCs retain previous profile behavior.
- Modern experience progress is within-level; all character panels show maxed text at threshold0. Hurt-animation reference remains the authored table's finite max evade (not level1000).
- Player dashboard rows are read-only formula previews (1..1000), including adding a preview row. NPC add uses createDefaultLevelDetail instead of multiplying the previous row. No manual database changes/migration.
