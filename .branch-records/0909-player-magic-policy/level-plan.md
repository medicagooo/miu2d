# 单级武功补全到10级方案（未实施）

2026-09-09，Asia/Singapore。依据三个游戏公开 game/{slug}/api/data 的只读结果及当前引擎。逐项标识、归属、基础数值和已有等级表见同目录 level-audit.json；此文件仅包含分析所需武功字段，不含账户或存档。

候选共96条（按游戏+键计数，同名不同键不合并），全部是 levels=null/空表，并非显式只有Level1。默认maxLevel可能为10，但levelupExp=0，常规经验不能升级。已有多级表不在本次补全范围。两个疑似升级特效暂不补级，也未擅自从玩家目录排除；实施前核实配置调用。

## 推荐设计

1. 为96个候选建立按游戏+完整技能键索引的“玩家成长覆盖表”，保留原始NPC记录及公共武功缓存。只有玩家学习、玩家等级计算和玩家存档恢复使用覆盖表；NPC施法、伙伴与未列入技能仍走原配置。不要在共享getMagic缓存内直接改写NPC的levels。
2. 每条覆盖表补齐1—10级、最高等级10，1级保留现有效果和操作手感。已有多级武功不自动修正；记录发现的异常供另项处理。
3. 各技能先选同游戏、同移动/伤害类型的成熟玩家技能作为参照；按单体、扇形/范围、追踪、毒/冰控制、辅助分组。先验证参照经验单调、伤害公式正确；例如当前新剑侠“幻影飞狐”部分等级经验下降且效果为负，不适合作通用模板。
4. 对现有effect非零技能，可按下表对1级数值插值取整。对effect=0技能必须保留“角色攻击力”语义，推荐玩家覆盖表新增可选的等级effectExt增量，1级增量0，后续按同类参照的实测总伤害预算分配；不要把0乘倍率，也不要直接切成固定effect。当前公开MagicLevelSchema不支持effectExt，实施时需给玩家覆盖表专用类型/合并器支持，不能仅提交一张数据库等级表。
5. 当前getMagicAtLevel会把effectLevel直接设为技能等级；区域弹幕数量和冰冻/中毒等效果会受此影响。新覆盖表应明确分离“成长等级”和“弹幕/控制效果等级”，默认保留1级的弹幕、速度、持续时间及控制强度，仅对实测通过的条目在4/7/10级解锁形态成长。不要同时放大单发伤害、弹数、命中次数和控制时长。

经验参考来自已有“魂牵梦绕”曲线；仅作候选模板，每游戏应按同类武功练级耗时校准。levelupExp是累计阈值：1级300表示累计300升2级，9级50000表示累计50000升10级，不是每级再加50000。1—9级严格递增且为正，10级不再增长。

原内力为0的技能不套倍率：1级维持0，2—10级依据同类技能单位总伤害耗蓝确定独立非零曲线，避免免费高级范围攻击；具体数值在技能逐项测量后锁定。控制与辅助类不套伤害倍率，保留控制强度起步，仅优化耗蓝/冷却需另设专用可选覆盖字段。

这两类公式必须分开测：新剑侠通常是Effect+Attack；月影/剑侠2非零Effect通常替代Attack；Effect=0均回落realAttack。仅检查配置数值单调不足以证明实际伤害单调。

## 实施顺序与验收

- 第一批：柳叶飞刀、水系攻击1、火系攻击3、镇狱破天劲等覆盖零/非零效果、单体/范围/控制的代表条目，先完成玩家独立覆盖与等级合并测试。
- 第二批：每个游戏逐项锁定参照技能、1级基线、10级总输出/耗蓝目标、每级数据和弹幕/控制上限，再扩至清单全部候选。名单包括重复名称和内部变体，需检查联动/子技能引用，不能重复叠加成长。
- 覆盖表校验：键唯一、1—10连续、经验严格递增、满级封顶、数值有效；除明确许可字段外，原行为字段和1级效果保持。
- 战斗验收：固定角色等级/装备、单体及多目标场景，对1/4/7/10级测试总伤害、命中次数、耗蓝、施法频率、控制覆盖率；再用低/中/高攻击角色验证无等级提升反而降伤的问题。
- 兼容验收：NPC同一技能行为不变；旧客户端不依赖新增字段；已有存档不删除武功、不清零经验，玩家旧存档读取获得覆盖规则；高于10的异常存档仅在未来实施明确规范化方案后处理，不静默改写。
- 本阶段不改线上数据库。推荐先本地文件覆盖方案，构建测试后另行发布；若未来选择持久化到数据库，须先说明确切目标、操作和影响并获得确认。
